## 二、任务要求

首期 5 个模块。**一周可承诺范围 = M1 骨架 + M2 + M3 + M5 的 gate 主路径**；M1 的候选打分细化、M4 的三口径、M5 的报告格式化如时间不足，**在 `plan/05` 与 README 中显式标为"第 2 周"**，不得静默缩水。

**数值口径（QI 候选打分、缺失值三选一、k·l·t 定义、剪枝与预算、退出码）只在 `data/README.md` §四定义一次**，代码、文案、文档一律引用该节。以下各模块的"确定性纪律"是该口径在各模块的落地方式，不另立第二套定义。

### 模块 M1：角色声明与 QI 候选

- **输入**：一张表（CSV / TSV；单表）＋ 列角色声明（`qi` / `sensitive` / `direct-identifier` / `date-precision`）。
- **输出**：归一化 schema JSON（每列的声明角色、推断类型、基数、唯一值率、候选打分、是否参与后续计算）。
- **引擎**：按声明做类型归一（日期只按声明的精度取粒度，如 `year` / `month` / `day`；字符串不做隐式清洗）。QI **候选**由**基数与唯一值率**给出可解释打分（例：唯一值率越高、基数在中高区间 → 越像准标识符），并在报告里写明打分的两个数，**不猜列名**——明确对照 piiscope 的 `_QI_NAME_HINTS` 硬编码路径。
- **角色语义（硬约束）**：`direct-identifier` 列**默认不参与** k/l/t 计算（参与即 k=1 恒成立，结论无信息量），但在报告中列出"若泄露则直接重识别"；`sensitive` 列参与 l/t 计算，不参与等价类键；**未声明即不参与**——不做"猜它可能是 QI"的自动纳入。
- **确定性纪律**：候选打分是列内容的纯函数；同一表 + 同一声明在任意机器上输出逐字节相同的 schema JSON（键序固定、浮点格式固定、不写时间戳）。
- **验收**：① 给定夹具表的候选打分可复算，打分分数与两个输入统计量在报告中同时出现（可手算核对）；② "该不该算 QI"由**人**在声明里定，工具只给候选与理由，**不得自动改角色**；③ 未声明列出现在"未参与"清单里，不静默丢弃。

### 模块 M2：等价类引擎

- **输入**：表 + 已声明的 QI 列集合 + 缺失值策略（显式三选一）。
- **输出**：最小 k、每类大小分布（直方图 + 类数）、l 值、t 值、**每处违例的等价类键与行号清单**。
- **引擎**：按 QI 列的值元组分组（等价类键 = 声明顺序的 QI 值元组，规范化形式由 `data/README.md` §四定义）；k = 最小类大小；l = 敏感列在类内的最小不同取值数；t = 类内敏感列分布与全表分布的最大距离（距离口径 §四单点定义）。**违例清单必须可直接手算**：每条给"分组键 + 计数 + 行号"，不允许只给一个总数。
- **缺失值语义（显式三选一，必须由调用方指定，无默认静默行为）**：
  1. `drop`——含缺失的行**不参与**分组，单独计入"未裁决行数"；
  2. `single-column`——按"缺失值算作该列的一个普通取值"参与分组（`NULL` 自成一级）；
  3. `separate-class`——含缺失的全部行合并为一个**独立等价类**，与正常类分开报告，且该类的 k 单独给出。
  三种策略的结果**分别可复算**，报告首行必须打印实际使用的策略名；不指定则**报错退出**，不猜。
- **确定性纪律**：分组键用稳定排序（按键的规范化字符串排序，不依赖字典插入序）；同表同声明同策略 → 逐字节相同输出（行号清单顺序固定）。
- **验收**：① 三种缺失策略各有一组专门用例，且**针对 sdcMicro #363（缺失值下 l 值算错）的坑**设独立测试（同一夹具在 `single-column` 与 `separate-class` 下的 l 值分别人工推导并断言）；② 最小 k、类数、各违例行号可被人工按输出复算；③ 空表、单行表、全 QI 相同的表三种边界有定义行为。

### 模块 M3：组合攻击面搜索 ★招牌

- **输入**：表 + 全部候选 QI 列（含声明与打分）+ 阈值（k 门限、可选的 l/t 门限）+ 搜索预算。
- **输出**：
  1. **最小崩塌集**：一个 QI 子集 S，使得 S 下 k ≥ 阈值，而**再加任意一列**（来自候选池）k 就跌破阈值；
  2. **k 崩塌曲线**：按子集大小分层的 k 最小值 / 违例行数；
  3. 每个被评估子集覆盖的**暴露行数**（落入 k < 阈值 的类中的行数）；
  4. **完整性声明**：`已穷尽` 或 `被预算截断`（截断时必须给出已评估子集数与总候选子集数的关系）。
- **引擎**：按**基数反单调剪枝**枚举子集：
  - 先按单列基数升序排列候选列；
  - 若子集 S 的 k 已低于阈值，则任何 S 的超集 k 只会更低（**仅在"只增加分组列、不引入泛化/抑制"的语义下成立**），因此可以剪掉 S 的全部超集；
  - 枚举顺序固定（按子集大小升序、同大小按列的规范化名排序），结果与剪枝路径无关地可复现；预算以"已评估子集数"计数，到达预算即停并标记 `截断`。
- **确定性纪律**：剪枝只影响**速度**，不影响**结论正确性**（剪枝条件本身用测试锁定）；输出中必须显式区分"因剪枝而无需评估"与"因预算而未评估"——**这两种不可混为一谈**，后者必须让完整性声明变为 `截断`。
- **验收**：① 在**植入真值**的合成夹具上，最小崩塌集与真值逐项命中（真值由夹具生成器写入，不由搜索器自己标注）；② 同一输入两次运行输出逐字节相同；③ 故意把预算设小，必须输出 `截断` 而不是伪造"已穷尽"；④ 边界：单列已达阈值（最小崩塌集为空集，需明确表达）、全部列都不达标（明确报"无解"）。
- **完整性风险（必须写进产品输出，也必须写进本文档）**：上述剪枝依赖 **QI 集合单调性**——即"多加一列分组，k 不升"。一旦引入**泛化**或**抑制后再重算**（例如 M2 的 `drop` 策略下，加列会改变被丢弃的行集），**单调性被破坏**，剪枝可能漏掉解。因此本模块**只承诺在"固定行集 + 只做分组"的语义下穷尽**；任何启用泛化/抑制/行过滤的组合，一律标记 `截断（单调性不适用）`，不得声称穷尽。这是已知的方法论边界，不是实现缺陷。

### 模块 M4：逐记录风险与攻击者模型

- **输入**：M2 的等价类结果 + 攻击者模型选择。
- **输出**：逐记录风险表（每行：记录行号、所属等价类 id、类大小、在三个攻击者口径下的风险标记）；汇总的唯一记录数。
- **引擎**：三种攻击者口径**写死并文档化**（口径措辞进 `data/README.md` §四）：
  - `prosecutor`——攻击者已知目标在表里，问"能否从类中认出他"（类内唯一定位）；
  - `journalist`——攻击者不知道目标是否在表里，问"能否从类中锁定某个具体个体"（含成员推断的保守处理）；
  - `marketer`——攻击者只关心"能否把类缩到很小的人群"，不关心具体是谁。
- **确定性纪律**：三种口径的判定是等价类大小与敏感列的纯函数；逐记录行号排序固定；同一输入两次运行逐字节相同。
- **验收**：口径定义写进文档并被测试引用（测试名带口径名）；对植入夹具的唯一记录，行号与类 id 与真值一致。

### 模块 M5：可复算 gate + 判据文件

- **输入**：判据文件（声明阈值：k 门限、可选 l/t 门限、缺失策略、搜索预算）＋ 表 ＋ 输出目录。
- **输出**：① 机器可读 JSON 判据结果；② 人类可读报告（含每条违例的"分组键 + 计数 + 行号"）；③ **退出码**。
- **退出码（`data/README.md` §四单点定义，代码与 CI 文档只引用）**：`0` = 通过；`1` = 有违例（fail-closed）；`2` = 输入/判据无效（无法裁决，不得当作通过）。**任何"算不出来"的情况一律不得退化为 `0`**。
- **确定性纪律**：同一表 + 同一判据文件 → 相同 JSON（键序、浮点格式、数组顺序全部固定）+ 相同退出码；报告中不含时间戳、主机名、绝对路径（路径以 `--root` 相对化）。
- **验收**：① 判据文件是**政策输入**：改阈值只改判据文件，不改代码；② 每条违例可被第三方按报告"手算复核"（分组键 + 计数 + 行号三件套齐全）；③ 输入缺列 / 类型不符 / 缺失策略缺失 → 退出码 `2`，有明确错误信息；④ 可直接挂 CI（示例 workflow 片段随仓库提供）。

### 扩展项（不进首期）

- **泛化层级自动生成**：给定列的取值分布，生成层级并重算 k——会破坏 M3 的单调性前提，**必须与 M3 的完整性声明一起重做**。
- **抑制方案优化**：对应 sdcMicro #354 的"过度抑制"，需要与 ARX / sdcMicro 正面比较，首期不做。
- **ε 账本（第二产品线）**：跨流程的 DP 预算累加与 fail-closed 门禁。首期不做，原因见 `plan/00-README总览.md` 弃选项表（组合数学已是商品，差异只剩胶水）。

## 六、边界与非目标

- **不做合规审计报告**：不产出检查单、不评制度与流程、不给"合规/不合规"结论——那会滑回本系列已有的主题，属于撞域。本题只输出**量**（k/l/t、组合、行号）与**按声明阈值的 gate 结论**。
- **不做泛化/抑制的自动方案优化**：那是 ARX 与 sdcMicro 的战场。本题只在"固定行集 + 只做分组"的语义下搜索；一旦引入泛化/抑制，只标记"单调性不适用"，不冒充最优方案。
- **不做合成数据生成**：SDV 3580★ 已占位，且合成数据的隐私测量已被 anonymeter 110★ 占位。本题的输入是**待发布的原始表**，不是合成表。
- **不做 DP 库**：diffprivlib 919★ / OpenDP 444★ 已占位，ε 账本也因组合数学商品化而列为弃选项。
- **隐私红线**：**不要求任何真实敏感数据**；**纯本地、零网络调用**（安装后 `--help` 到报告生成全程无出站请求）；示例数据全部**合成**，合成纪律见 `data/README.md` §三；仓库**不收录**任何真实个人数据、真实身份证号、真实手机号（`.gitignore` 排除 `*.csv` 示例数据目录）。
- **品牌隔离**：命名、模块词系（扫描器 / 攻击面 / 等价类 / 崩塌集）与文档模板独立；文档不提名任何姊妹项目，不复用"合规项""风险条款""检查单"作为产物名。
- **首期范围限定**：单表、单机、Python CLI；不做分布式、不做多表链接攻击（record linkage）、不做差分隐私机制。
- **搜索完整性风险（必须显式声明）**：M3 的剪枝只在"**只做分组、不引入泛化/抑制/行过滤**"的前提下成立。任何改变行集或改变列值语义的操作都会破坏单调性，此时工具**只能报告"被预算截断"或"单调性不适用"**，绝不允许输出"已穷尽"。这条是产品语义的一部分，必须出现在 CLI 输出、JSON 与 README 三处，而不只是文档脚注。
- **结论纪律**：所有"最小 k""最小崩塌集""违例行数"都是**在声明的角色、缺失策略、阈值与预算下的结果**，不是"该表的绝对隐私水平"；报告首屏必须回显这四项声明，禁止脱离上下文引用数字。
