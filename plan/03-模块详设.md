# 03 · 模块详设（M1–M5）

> 数值口径（k/l/t 定义、缺失策略、打分公式、剪枝、退出码）**只在 `data/README.md` §四定义**。
> 本文件写**输入 / 输出 / 算法 / 失败路径 / 验收**，以及会打挂测试的既定口径（§K）。

## 模块 M1 · 角色声明与 QI 候选

**输入**：`--table`（CSV/TSV，UTF-8，首行表头）+ `--decl`（JSON）。
**输出**：`<out-dir>/schema.json`。

声明文件结构（闭合，未知键即 `DeclarationError`）：

```json
{
  "columns": {
    "age":    {"role": "qi"},
    "zip":    {"role": "qi"},
    "dob":    {"role": "date-precision", "precision": "year"},
    "name":   {"role": "direct-identifier"},
    "disease":{"role": "sensitive"}
  }
}
```

**算法**
1. `tableio.read_rows()` 读入，得到表头顺序、行列表（每行 = 值列表 + 行号）。
2. 逐列按角色归一：`date-precision` 只按声明粒度截断（`year` → 前 4 位数字；`month` → `YYYY-MM`；`day` → `YYYY-MM-DD`）；
   截断失败的值 → `InputError`（**不猜、不静默置空**）。其余角色**不做任何隐式清洗或类型推断**（字符串原样保留）。
3. 逐列计算 `cardinality`（缺失不计）、`non_missing`、`uniqueness_ratio`、`qi_score`（公式见 §4.2）。
4. 输出：每列 `role / inferred_type / cardinality / non_missing / uniqueness_ratio / qi_score / participates`，
   外加 `unparticipating`（未声明列 + `direct-identifier` 列）与 `direct_identifier_warning` 清单。

**失败路径**：声明列名不在表头 → `DeclarationError`（列出差集）；角色不在枚举 → `DeclarationError`；
`date-precision` 缺 `precision` 或粒度不在枚举 → `DeclarationError`；空表 → 输出 `cardinality=0`、`qi_score=null`、`undefined_reason="empty_table"`（**不报错**：空表是可裁决的边界）。

**验收**（对应 `plan/01` §M1 验收 ①②③）：候选分数与两个输入统计量同屏；角色**只由人声明**，工具不改；未声明列进 `unparticipating`。

## 模块 M2 · 等价类引擎

**输入**：表 + 声明 + `--missing-policy`。
**输出**：`<out-dir>/scan.json`（k/l/t、类大小直方图、每处违例三件套）。

**算法**
1. 取声明为 `qi` 的列，**按声明文件里的列名顺序**构成键序（不是 CSV 表头顺序；声明顺序即语义顺序，见 §4.3）。
2. 缺失判定：空串、`NA`、`N/A`、`null`、`NULL`、`-`（大小写敏感，逐个在 `data/README.md` §4.4 旁注里定死；本模块只实现一次，
   由 `tableio.missing_set()` 单一出口提供）。**注意**：`""` 不进入字符串清洗路径，只是因为它在缺失集合里。
3. 按缺失策略分组：
   - `drop`：含缺失的行**不进任何类**，计入 `undecided_rows`（行号清单）；
   - `single-column`：缺失值作为该列的一个普通取值 `NULL` 参与键；
   - `separate-class`：含缺失的行全部并入一个独立类 `__MISSING__`，`k` 单独输出为 `missing_class_k`。
4. 计算 `k`、`l`（逐 sensitive 列取最小值）、`t`（逐类逐列总变差距离，取最大）。
5. 违例判定：`class_size < k_threshold`（或 `l < l_threshold` / `t > t_threshold`）。每条违例输出
   `key`（规范化键字符串）、`values`（有序值元组）、`count`、`row_numbers`（升序）。

**失败路径**：无 `qi` 列 → `DeclarationError`（"未声明任何 qi 列，无法分组"）；无 `sensitive` 列且声明了 l/t 门限 → `CriteriaError`；空表 → `k=null` + `undefined_reason="empty_table"`，退出码按"无法裁决"处理。

**验收**：三策略各一组用例；`single-column` 与 `separate-class` 下的 l 值分别人工推导并断言（对 sdcMicro #363 型坑）；最小 k、类数、违例行号可手算复现；空表/单行表/全同表边界有定义行为。

## 模块 M3 · 组合攻击面搜索 ★招牌

**输入**：表 + 候选 QI 池（声明为 `qi` 的列 + `--include-candidates` 时纳入的高分未声明列，**仅本模块允许**，报告显式标注）
+ `--k`（必需）+ `--budget`（必需）+ 可选 l/t 门限。
**输出**：`<out-dir>/search.json`。

**算法**
1. 候选列按 `cardinality` **升序**（同基数按列名码位序）编号。
2. 按子集大小 `1..n` 升序枚举；同大小按列名码位序的字典序。
3. 对子集 `S` 计算 `k(S)`（复用 M2 的分组函数，**不重新实现**）。
4. 剪枝：`k(S) < k_threshold` → 跳过 `S` 的全部超集，计入 `pruned_subsets`（与 `evaluated_subsets` 分开计数）。
5. 预算：以 `evaluated_subsets` 计数，达到 `--budget` 即停，`completeness = "budget-truncated"`。
6. 最小崩塌集：`k(S) ≥ threshold` 且所有一列扩展都 `< threshold`（或 `undefined`）。单列已达标 → `minimal_collapse_sets: [[]]` + `empty_set_witness: true`。
7. 全部候选均不达标 → `verdict = "no_solution"`。
8. 分层曲线：按 `|S|` 聚合 `min_k` 与 `exposed_rows`（落入 `k<threshold` 类的行数）。

**完整性三态**：`exhausted` / `budget-truncated` / `monotonicity-not-applicable`。
`monotonicity-not-applicable` 只在 `--missing-policy drop` 且候选池含未声明列、或将来启用泛化/抑制时出现；
**当前实现的触发条件写死在 `m3_search.completeness()` 一处**，并有测试断言"drop 策略下加列会改变行集 → 状态必须是 `monotonicity-not-applicable`，且不得输出 `exhausted`"。

**失败路径**：`--budget <= 0` → `CriteriaError`；候选池为空 → `DeclarationError`；`--require-exhaustive` 且 `budget-truncated` → 退出码 `2`。

**验收**：植入真值夹具上最小崩塌集逐项命中；两次运行逐字节相同；预算设小必须 `budget-truncated`；空集/无解两种边界显式表达。

## 模块 M4 · 逐记录风险与攻击者模型

**输入**：M2 的等价类结果 + `--attacker`（三选一，必需）。
**输出**：`<out-dir>/risk.json`。

**口径（写死，措辞与 `data/README.md` §4.8 一致，测试名带口径名）**

| 口径 | 判定 | 备注 |
| --- | --- | --- |
| `prosecutor` | 类内唯一定位：`class_size == 1` 即该记录被识别 | 目标已知在表内 |
| `journalist` | 类内可锁定具体个体：`class_size <= 2` 即判"可锁定"（含成员推断的保守处理：`class_size == 2` 时另一人即被推出） | 目标是否在表内未知 |
| `marketer` | 类缩到很窄人群：`class_size < 3`（即 ≤ 2 人）视为"可归入小人群" | 不关心具体是谁 |

三个阈值**写死在这张表里**，并由测试以口径名命名锁定；以后要改必须同步改 `data/README.md` §4.8。

**失败路径**：`--attacker` 不在枚举 → argparse `2`；无等价类结果（空表）→ `records=[]` + `undefined_reason="empty_table"`。

**验收**：唯一记录的行号与类 id 与真值一致；逐记录行号排序固定；双跑逐字节一致。

## 模块 M5 · 可复算 gate + 判据文件

**输入**：判据文件 JSON + 表 + `--out-dir`。
**输出**：`gate.json`（机读）+ `gate.md`（人读）+ 退出码。

判据文件（闭合，未知键即 `CriteriaError`）：

```json
{
  "table": "examples/adult/adult.csv",
  "declaration": "examples/adult/declaration.json",
  "missing_policy": "drop",
  "thresholds": {"k": 5, "l": null, "t": null},
  "search": {"enabled": true, "budget": 2000, "require_exhaustive": false}
}
```

**算法**：校验 → 调 M2 →（可选）调 M3 → 组装结论 → 按 `data/README.md` §4.6 映射退出码。
报告首屏回显四项声明（角色 / 缺失策略 / 阈值 / 预算），逐条违例给"分组键 + 计数 + 行号"。

**失败路径**：判据缺 `missing_policy` → `2`；`table` 指向不存在的文件 → `2`；判据里的阈值类型不符（`k` 不是正整数）→ `2`；
完整性 `budget-truncated` 且 `require_exhaustive=true` → `2`。**任何"算不出来"的情况不得退化为 `0`。**

**验收**：改阈值只改判据文件；每条违例可手算复核；输入缺列/类型不符/缺策略 → `2` 且有明确信息；CI 可直接用退出码。
